01 Overview

VibeLive answers one question continuously: what is happening around a given point in a city right now, and is it changing?

Ingest workers poll external providers on independent schedules and write normalized observations into a single raw table. Analysis workers read those observations over sliding time windows, compare each window against the one before it, and record a conclusion. Only conclusions that moved materially are sent to a language model for a sentence of narration — everything else carries the previous text forward.

The system is deliberately small: four processes, one database, no queue, no cache, no message bus. That is a fit for a single operator and a few locations, and every boundary that would need to become a queue later is already a boundary now.

Design premise

Every number the system displays must be something that actually happened. Where no free real source exists — crowd density, ambient noise — the category stays empty and says so, rather than being filled with synthetic data that would look identical to real data three weeks later.

02 Process topology

Four containers. migrate is not a service that stays up — it runs to completion and exits, and both long-lived processes are gated on its success. That ordering is what makes a half-migrated database unreachable rather than merely unlikely.

03 The pipeline

Data moves in one direction through four stages. The two shaded gates are where the system protects itself: one against duplicate observations, one against unnecessary spend.

The shape of an observation

A single provider call usually returns several numbers at once — temperature, humidity, wind and cloud cover arrive together. Each becomes its own row, distinguished by metric and carrying its own unit. Two timestamps are kept deliberately: observed_at is when the provider saw it, created_at is when we stored it. Every trend window is computed on the former.

05 Decisions worth knowing

  • One asyncpg pool per process, in a shared module vibelive/db.py is imported by both the API and the worker runner. Each calls init_pool() once at startup; neither opens connections per request. JSON codecs are registered on the pool's init hook, because asyncpg otherwise returns JSONB as a string.
  • Migrations are immutable, and the runner enforces it Each file's sha256 is recorded when applied. Editing an applied migration makes the next run fail loudly. The previous approach — Postgres' docker-entrypoint-initdb.d — silently ignored every edit once a data directory existed, which is a far worse failure because it looks like success.
  • An advisory lock wraps the migration run The API and worker containers start together and would otherwise race to apply the same file. With the lock, the second migrator blocks and then finds nothing to do.
  • Ingestion is idempotent by construction Providers refresh on their own schedule; polling faster returns the same observation again. Stored twice it becomes two independent samples, biasing every average and every trend magnitude downstream — silently, with no error. A dedup_key and a partial unique index make the repeat a no-op.
  • Trend magnitude is a unitless fraction (cur_avg − prev_avg) / abs(prev_avg), so 0.29 means +29%. Classification happens in Python, not SQL, so it is testable without a database.
  • The AI layer is a protocol with a null implementation The default provider assembles a real sentence from the aggregates and costs nothing, so the entire pipeline — including cost telemetry — is demonstrable before any key exists. Swapping to a local model or a hosted API touches one factory function.
  • Prompts receive aggregates, never raw payloads Roughly ten scalars and at most six bucketed points, budgeted under 250 input tokens. A single raw provider payload is about 400 tokens on its own, and a window holds several.

06 Data sources

Only sources that are free and return real observations are in scope. Where nothing qualifies, the category stays empty.

Proxy, not simulation

Crowd density has no free direct feed. Deriving it from real transit arrivals is a defensible proxy computed from real observations, and it is labelled as such — transit_arrivals, not crowd_index. That is a different thing from generating a plausible-looking curve, which would be indistinguishable from real data in every screenshot that ever leaves the machine.

07 Cost control

The AI leg is the only part of the system whose cost scales with activity, so it is gated rather than trusted. Six checks run before any request, cheapest first, and every attempt is recorded in ai_calls — which is what makes the spend claim verifiable rather than aspirational.

With a local model the marginal cost is zero regardless; the gates still matter, because they bound latency and keep the worker loop from spending minutes narrating windows nobody will read.

What phases 0–2 proved

  • A from-scratch migration run reproduces the original schema byte-for-byte under pg_dump --schema-only.
  • Two migrators started concurrently apply each file exactly once.
  • Editing an applied migration fails the next run with a checksum error.
  • Inserting the same dedup_key twice leaves one row, with the first value intact.
  • Stopping the database degrades /health without crashing the API, and the pool recovers on its own.

09 Operations

Everyday

# bring the stack up — migrations run before anything serves
docker compose up -d --build

# inspect migration state
docker compose run --rm migrate python -m vibelive.migrate status

# author the next migration
docker compose run --rm migrate python -m vibelive.migrate new add_something

Reset

# destroys all data; schema and seeds rebuild from migrations/
docker compose down -v && docker compose up -d --build
Before this host is reachable

ENABLE_EXPLORER must be set false. The explorer's query endpoint runs arbitrary SQL — a read-only transaction with a statement timeout stops writes and runaway scans, but it still reads every row in the database. That is acceptable on localhost and nowhere else.

Known gaps

  • No backups yet. Accumulated history is unrecoverable — free provider tiers expose no history endpoint — so a nightly pg_dump lands with the first ingest worker, not later.
  • No authentication. Correct for a single operator on localhost; a shared secret is required before the sensor ingest endpoint exists.
  • Per-category window sizes, retention horizon, and display timezone are still defaults rather than decisions.
